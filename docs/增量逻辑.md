# 增量同步逻辑

> 关联代码：`store/syncer.go`、`store/sync.go`、`store/es.go`、`store/mysql.go`、`store/monitor.go`、`common/window.go`

## 1. 作用

增量同步实时地把 ES 中新写入的事件数据，按“固定时间窗口”拉取并写入 ADB（MySQL）。每 **interval 秒** 触发一次，只处理 **上一已结束且已过了延迟补偿（lag）** 的窗口，从而规避 ES 写入延迟导致的漏数。

## 2. 触发机制

```
main.go
  └─ StartIncremental(ctx)
       └─ Syncer.StartIncremental(ctx)     // store/syncer.go
            ├─ 立即执行一次 runIncremental()
            └─ time.NewTicker(interval 秒) 循环触发 runIncremental()
```

- 入口：`main.go` → `Manager.StartIncremental` → `Syncer.StartIncremental`
- 定时器：`interval` 秒（配置 `sync.interval`，默认 `10`）
- 条件：ES 与 ADB 均就绪（`mgr.ES != nil && mgr.MySQL != nil`）才运行，否则跳过本轮
- 停止：进程收到 SIGINT/SIGTERM 后通过 `context cancel` 退出

## 3. 单轮处理流程（runIncremental）

```
1) 计算目标窗口
   win = IncrementalWindow(now, interval, lag)
       = [ (now - lag) 向下对齐 interval - interval , (now - lag) 向下对齐 interval )
       = 最近一个「已结束且早于 (now-lag)」的窗口

2) 窗口同步 SyncWindowWithRetryResult(win)
   ├─ 查 ES：SearchByRangeMs(startMs, endMs, max_size)
   │    ├─ 过滤 method.keyword = (配置 es.method，默认 addEventLog)
   │    ├─ dateField(range: [startMs, endMs))，升序
   │    └─ 命中正文需包含 es.strip 前缀（默认 "用户事件记录==="），并解析出 es_timestamp
   ├─ 解析：BuildFromESRecords → ConvertMap → MapToEventLog（详见《数据转换逻辑》）
   └─ 写入 ADB：BatchInsertIgnore（REPLACE INTO，按 batch_size 分批）
       └─ 失败按 max_retry 次指数退避重试

3) 记录监控：Monitor.RecordIncremental(win, hits, written, dur, err)
   └─ 追加到内存历史（保留 1 小时），SSE 推送 "incremental" + "pipeline"
```

- `hits` = ES 命中条数（本窗口有效记录数）
- `written` = 实际写入 ADB 的条数
- 若 `hits == max_size` 会打 `Warn` 提示可能有遗漏（单窗口触及上限）

## 4. 相关配置

| 配置项 | 字段 | 默认值 | 说明 |
|---|---|---|---|
| 同步间隔 | `sync.interval` | 10 | 触发周期（秒），窗口大小也由此决定 |
| 延迟补偿 | `sync.lag_seconds` | 60 | 规避 ES 写入延迟，基准回退（秒） |
| 单窗口最大拉取 | `sync.max_size` | 1000 | ES 单窗口最多条数 |
| 批次写入 | `sync.batch_size` | =max_size | 单条 REPLACE INTO 行数 |
| 重试次数 | `sync.max_retry` | 3 | 失败最大重试次数 |
| 重试初始延迟 | `sync.retry_delay` | 1 | 秒，指数退避 |
| 重试最大延迟 | `sync.retry_delay_max` | 10 | 秒 |
| 事件前缀（ES） | `es.strip` | 用户事件记录=== | 正文事件前缀标识，识别并去掉头部 |

## 5. 时间窗口示例

设 `interval=10s`、`lag=60s`，当前时刻 `23:27:31`，则：

- 基准 = 23:27:31 - 60s = 23:26:31
- 基准向下对齐 10s = 23:26:30
- 目标窗口 = `[23:26:20, 23:26:30)`

即每次只同步“已经稳定写入、不会再变化”的完整窗口，避免读到 ES 未写完的数据。

## 6. 重试策略

`SyncWindowWithRetryResult`：

- 最多尝试 `maxRetry+1` 次（含首次）
- 指数退避：`retry_delay` 每次翻倍，封顶 `retry_delay_max`
- 全部失败后返回最后一次 `hits/written` 与 error；无论成败都会记录进监控并在 SSE 展示 status=fail/ok

## 7. 监控与内存保留

- 每次增量记录为一个 `IncrementalPoint`，缓存在内存数组
- 保留窗口：**1 小时**（`monitorRetention = time.Hour`），每分钟清理过期记录
- 事件流：
  - `incremental`：单条增量结果（`IncrementalPoint`）
  - `pipeline`：接线图实时快照（`PipelineSnapshot`）
- 前端在连接 `/monitor/sse` 时首包 `history` 一次性回放最近 1 小时全部增量。

## 8. 边界/注意点

- 窗口是左闭右开 `[start, end)`，跨天、跨整点均自动对齐
- 单窗口 `hits == max_size` 只告警不中断（可能存在遗漏，建议调大 `max_size`）
- 解析异常的单条记录会被跳过并 `Warn`（例如缺 `id`、`createTime` 格式错）
