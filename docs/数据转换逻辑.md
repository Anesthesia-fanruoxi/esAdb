# 数据转换逻辑（ES 解析 → 切割 → 转换 → 存储 ADB）

> 关联代码：`store/es.go`（拉取+头部裁剪）、`store/mysql.go` 之 `BuildFromESRecords`、`common/convert.go`、`store/mysql.go` 之 `BatchInsertIgnore`、`model/event_log.go`

增量与补全都复用同一条“单窗口同步”链路，其中数据从 ES 正文一路转换写入 ADB 分四步：**拉取 → 切割 → 字段转换 → 批量写入**。

```
ES 查询命中（method 过滤 + 时间范围）
   │  SearchByRange // store/es.go
   ▼
ESRecord{ Content, EsTimestamp }        ── ① 拉取 + 头部裁剪(strip)
   │  BuildFromESRecords // store/mysql.go 逐条
   ▼
ConvertMap(content)  →  map[string]string  ── ② 竖向切割成 KV
   │  common/convert.go
   ▼
MapToEventLog(map)  →  *model.EventLog      ── ③ 字段转换 / 校验 / 建模型
   │  (es_timestamp 由 ES 时间戳回填)
   ▼
BatchInsertIgnore(logs)  →  REPLACE INTO    ── ④ 分批写入 ADB
```

## ① 拉取与头部裁剪（store/es.go）

- 查询条件：`method.keyword = es.method`（默认 `addEventLog`）+ `dateField ∈ [start, end)`，按时间升序。
- 命中每条取出 `es.fields` 字段（默认 `content`）与 `es.dateField`（默认 `@timestamp`）时间戳。
- **头部裁剪（可配置）**：配置项 `es.strip`（默认 `用户事件记录===`）用于识别并去掉正文头部。
  - 不含 `strip` 的文档直接跳过；
  - 含 `strip` 的，取 `content[idx:]`（从 `strip` 出现处起保留）。
  - `common` 返回 `ESRecord{ Content, EsTimestamp }`，`EsTimestamp` 为该文档 ES 毫秒时间戳。

> `strip` 需以 `===` 结尾最为稳妥（与下方切割逻辑 `SplitN(content, "===", 2)` 匹配，`===` 前的内容视为会被去掉的标签）。

## ② 竖向切割（common.ConvertMap）

把一条 ES 正文（`xxx===k1:v1,k2:v2,...`）切割成键值 map：

1. `strings.SplitN(content, "===", 2)`：取 `parts[1]` 作为 body（`===` 前的是头部标签，此时已由 ① 裁剪但此处仍兼容）。
2. 处理 `extend:`：找到 `extend:` 的下标，把之前部分作为普通 KV 段，之后整体作为 `extend` 值。
3. 对 KV 段按 `,` 拆分，每一项按第一个 `:` 切出 `key:value`，清理空格后写入结果 map。
4. 返回 `map[string]string`（例：`id/type/phoneMd5/customerId/eventId/eventName/...`）。

## ③ 字段转换（common.MapToEventLog + 回填）

`BuildFromESRecords` 逐条、逐 key 处理：

- `id` 为空 → 跳过该条；
- `MapToEventLog`：把 map key 映射到 `model.EventLog` 结构体；`createTime` 需按 `2006-01-02 15:04:05`（本地时区）解析，解析失败则整条跳过并 `Warn`；
- `extend` 为 `"null"` 或空 → 置空；
- `EsTimestamp = ESRecord.EsTimestamp`（毫秒，来自 ES 时间戳而非正文时间）。

**字段映射（正文 KV → EventLog → ADB 列）**

| 正文 key | EventLog 字段 | ADB 列 |
|---|---|---|
| id | ID | id |
| type | Type | type |
| phoneMd5 | PhoneMd5 | phone_md5 |
| customerId | CustomerID | customer_id |
| eventId | EventID | event_id |
| eventName | EventName | event_name |
| channelId | ChannelID | channel_id |
| channelName | ChannelName | channel_name |
| client | Client | client |
| path | Path | path |
| ip | IP | ip |
| createTime | CreateTime | create_time |
| source | Source | source |
| appVersionType | AppVersionType | app_version_type |
| extend | Extend | extend |
| —（ES 时间戳） | EsTimestamp | es_timestamp |

## ④ 批量写入 ADB（store/mysql.go BatchInsertIgnore）

- 使用 **REPLACE INTO**，天然幂等（重复回填安全）。
- 参数按 `model.Columns` 顺序绑定 16 列占位符（`?,?,...`）。
- 按 `sync.batch_size`（默认 1000）分块，每块拼成一条多行 `REPLACE INTO ... VALUES (...),(...)...`。
- 单块失败立即返回错误（由外层重试/补全聚合处理）。返回 `written`（本窗口写入条数）。

## 示例

ES 命中正文：

```
...前置无关内容...
用户事件记录===id:abc123,type:1,phoneMd5:8f...,customerId:c001,eventId:e01,
eventName:点击,createTime:2026-08-28 12:00:00,source:Android,extend:{"page":"home"}
```

经过 ①②③④：

- ① 取 `strip=用户事件记录===`，从下标处保留；
- ② body = `id:abc123,type:1,...`，切出 KV map（`extend` 单独保留）；
- ③ 映射为 `EventLog`，`EsTimestamp`=该 ES 文档时间戳毫秒；
- ④ 分块 `REPLACE INTO app_event_log(...) VALUES(...)` 写入 ADB。

## 常见问题

- 命中数达到 `max_size` → `Warn`，可能遗漏，调大 `max_size`。
- 单条 `id` 缺失 / `createTime` 解析失败 / `content` 非字符串 → 该条被跳过（不中断整窗）。
- `strip` 改了新的前缀后，旧数据中不含该前缀的文档会被过滤不入库。
