# 补全（历史回填）逻辑

> 关联代码：`api/sync.go`、`api/monitor.go`、`store/sync.go`、`store/es.go`、`store/monitor.go`、`common/window.go`

## 1. 作用

把历史某个时间范围内 **缺失** 的窗口数据，一次性拉齐写回 ADB。用于首次上线、错过增量或数据修复等场景。

- 可指定 **开始 +（可选）结束** 时间
- **结束留空** 时，默认截止到当前 `(now - lag)` 的上一已结束窗口

## 2. 接口与入口

范围补全与窗口补全两条独立入口（互斥：同一时刻仅允许一个补全任务）：

```
POST/GET  /sync/backfill          // 范围补全（10 分钟初始窗口 + 命中自适应分裂）
 body: { "start": "2026-08-27 00:00:00", "end": "2026-08-27 17:00:00" }
POST      /sync/backfill/windows  // 窗口补全（并行，按指定/异常窗口列表）
 body: { "windows": [{ "startMs": 0, "endMs": 0 }, ...] }   // 单次 ≤ 4000，按 startMs 去重
```

处理链路（两个独立入口，各走各自的并行执行函数，互不影响）：

```
HandleBackfill (api/sync.go)
  ├─ 解析 start / end（毫秒时间戳 | "2006-01-02 15:04:05" | RFC3339）
  ├─ 边界对齐到 10 分钟窗口（store.BackfillBaseIntervalSec = 600s）
  ├─ CalcBackfillPlan → SplitWindowsMs 切分为初始 10 分钟窗口列表
  └─ BackfillWindowsAdaptive(windows, rangeStart, rangeEnd)  // 逐窗 SyncWindowAdaptive

HandleBackfillWindows (api/sync.go)
  ├─ 解析、校验并去重 windows（endMs>startMs，按 startMs 去重）
  └─ BackfillWindows(windows, rangeStart, rangeEnd)          // 逐窗固定 SyncWindow
```

> 注意：**仅范围补全接口（`/sync/backfill`）启用自适应窗口分裂，走独立的 `BackfillWindowsAdaptive`**；窗口补全（`/sync/backfill/windows`）沿用原有 `BackfillWindows`（固定 `SyncWindow`），增量写入走 `SyncWindow`，均保持不变。

## 3. 自适应窗口分裂（核心，仅范围补全）

为避免固定小窗口（如 10 秒）逐窗查询过慢，范围补全以 **10 分钟** 为初始（最大）窗口粒度，并在查询命中数过大时自动切小，兼顾速度与稳定：

- **单窗口 ES 拉取上限**：`SplitThreshold = 10000`（内建常量）。一次查询 `size=10000`，若该窗口 ES 实际命中数达到该值，说明窗口可能截断、数据仍密集。
- **逐级分裂梯级**：`10 分钟 → 5 分钟 → 2 分钟 → 1 分钟`。命中数低于上限的窗口整窗一次处理；达到上限则分裂为下一级更小窗口并递归查询。
- **边界**：已到最小粒度 1 分钟仍超上限时，直接补本次 `size=10000` 拉到的前 1w 条写入，超出部分静默忽略（1 分钟窗口一般不会达到 1w；若仍有差异，交由外部对比分析兜底）。
- 每个子窗口内部继续独立判断是否需要进一步切分。

流程：

```
SyncWindowAdaptive(win)
  1. ES 区间查询（size=10000）取命中数 rawHits
  2. rawHits < 10000           → applyWindowRecords 整窗写入
  3. rawHits ≥ 10000 且可再分  → 按下一级粒度 SplitWindowsMs 切小，逐个递归
  4. rawHits ≥ 10000 且已 1 分钟 → 直接写入前 1w 条，超出忽略（无告警）
```

- 稀疏区间：每个 10 分钟窗口仅 1 次查询（快）
- 密集区间：密度越高窗口越小（稳），避免单次大结果集超时/截断

## 4. 补全并行执行

配置项（`config.yaml` → `sync`）：

| 参数 | 说明 | 默认 |
|---|---|---|
| `backfill_workers` | 并行 worker 数 | 2（不超过 CPU 核数） |
| `backfill_pause_ms` | 每窗口完成后暂停毫秒 | 50（0=不暂停） |

两个入口共用公共执行体 `runBackfill`，但传入不同的单窗口处理函数（范围补全 `SyncWindowAdaptive`、窗口补全 `SyncWindow`）：

```
BeginBackfill(rangeStart, rangeEnd, totalWindows, firstWindow, lastWindow)
workers = backfill_workers（默认 2，上限 NumCPU）
windows 放入 channel，workers 并发消费
每个窗口：
  1. run(win)
     - 范围补全（BackfillWindowsAdaptive）→ SyncWindowAdaptive   命中过多则自适应分裂
     - 窗口补全（BackfillWindows）         → SyncWindow            固定窗口粒度
  2. RecordBackfillWindow(res)  // 推送 backfill_window 事件
  3. 每完成 5 个窗口或全部结束 → UpdateBackfillProgress
  4. pause_ms > 0 时 sleep，限流
EndBackfill()                   // backfillActive=false，记录 finishedAt
返回 BackfillSummary
```

- 单窗口失败 **不中断** 整批，记入 `summary.windows[].error`
- 结果按窗口 `startMs` 排序；失败明细是本次请求的结果汇报，**非断点续传**
- 数据仅供内存展示，重启即失效；**不记录断点/剩余区间**，失败窗口需整区重跑

## 5. 监控与 SSE

### 5.1 主页 SSE（`GET /monitor/sse`）

| event | 时机 | 数据结构 |
|---|---|---|
| `backfill` | 每 5 窗口完成 / 结束 | `BackfillProgressPoint` |
| `backfill_window` | 每个窗口完成 | `BackfillWindowPoint` |
| `pipeline` | 实时 + 5s 心跳 | `PipelineSnapshot`（含 `backfillActive`、`backfillProgress`） |

**BackfillProgressPoint**（侧栏 / KPI 用，不含 QPS）：

```json
{
  "at": 0, "atStr": "...",
  "totalWindows": 100, "completed": 60, "failed": 2,
  "totalHits": 4580, "totalWritten": 4560, "percent": 62.0,
  "rangeStart": "2026-08-27 00:00:00.000",
  "rangeEnd": "2026-08-27 01:00:00.000"
}
```

- `percent` = `(completed + failed) / totalWindows * 100`（封顶 100）
- **范围补全**：`totalWindows` 为范围内**单位窗口总数**（单位窗口 = 增量间隔 `Sync.Interval`，默认 10 秒），一个月的单位窗口数固定（如 interval=10 时为 259200），与自适应分裂粒度无关；`completed`/`failed` 按每个完成窗口覆盖的单位窗口数累加（10 分钟=60、5 分钟=30、2 分钟=12、1 分钟=6），故百分比反映**时间覆盖比例**
- **窗口补全**：维持字面窗口计数（`totalWindows` = 窗口数，每完成一个窗口 +1），不做换算

### 5.2 详情 SSE（`GET /monitor/backfill/sse`）

打开补全详情弹框时连接，**约 1Hz** 推送 `snapshot`（首包）与 `detail`。

**BackfillDetail** 结构：

| 字段 | 说明 |
|---|---|
| `backfillActive` | 是否进行中 |
| `progress` | 当前 `BackfillProgressPoint` |
| `session` | 会话元信息（开始/结束时间、首末窗口） |
| `qpsSeries` | 每秒 QPS 采样（写入 / 命中 / 窗口） |
| `runtimeSeries` | 服务指标采样（内存 / Goroutine / GC） |

**BackfillSessionMeta**（与 `plan.firstWindow` / `plan.lastWindow` 同形）：

```json
{
  "startedAtMs": 0, "startedAtStr": "...",
  "finishedAtMs": 0, "finishedAtStr": "...",
  "firstWindow": { "startMs": 0, "endMs": 0, "start": "...", "end": "..." },
  "lastWindow":  { "startMs": 0, "endMs": 0, "start": "...", "end": "..." }
}
```

弹框三部分：**本次进度**（含计时器）· **补全吞吐**（QPS 折线）· **服务信息**（运行时折线，单屏无滚动）。

## 6. 响应体

范围补全（`/sync/backfill`）：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "plan": {
      "hasEnd": false,
      "intervalMs": 600000,
      "lagMs": 60000,
      "rangeStart": { "ms": 0, "time": "2026-08-27 00:00:00.000" },
      "rangeEnd":   { "ms": 0, "time": "2026-08-27 15:59:40.000" },
      "firstWindow": { "startMs": 0, "endMs": 0, "start": "...", "end": "..." },
      "lastWindow":  { "startMs": 0, "endMs": 0, "start": "...", "end": "..." },
      "totalWindows": 96
    },
    "summary": {
      "totalWindows": 96,     // 初始窗口数
      "workers": 2,           // 实际并行 worker 数
      "totalHits": 123456,
      "totalWritten": 123450,
      "failed": 0,
      "windows": []           // 失败窗口明细（error 非空），正常为空数组
    }
  }
}
```

窗口补全（`/sync/backfill/windows`）返回 `{ "windows": <去重后窗口数>, "summary": BackfillSummary }`，`summary` 结构同上。

## 7. 错误处理

| 场景 | code / HTTP |
|---|---|
| ES 或 ADB 未就绪 | 503 |
| 请求体格式错误 | 400 / code=1 |
| 缺少 start | 400 / code=2 |
| start 无法解析 | 400 / code=3 |
| end 无法解析 | 400 / code=4 |
| 时间范围无效 / 未生成任何窗口 | 400 / code=5 |
| 已有补全任务在执行 | 409 / code=20 |

## 8. 与增量的关系

- **增量**：持续、每 `interval`（默认 10 秒）自动跑当前稳定窗口，固定小窗口，沿用 `SyncWindow`
- **补全**：
  - 范围补全（`/sync/backfill`）：以 10 分钟为初始窗口，命中密集时**自适应分裂**（10→5→2→1 分钟），走 `SyncWindowAdaptive`
  - 窗口补全（`/sync/backfill/windows`）：固定窗口粒度，沿用 `SyncWindow`
- 增量与窗口补全**保持原样**，仅范围补全启用自适应逻辑
- ADB 写入幂等（`INSERT IGNORE`），增量与补全均可重复回填、安全
