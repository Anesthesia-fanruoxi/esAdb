# 补全（历史回填）逻辑

> 关联代码：`api/sync.go`、`api/monitor.go`、`store/sync.go`、`store/sync_paged.go`、`store/es_paged.go`、`store/monitor.go`、`common/window.go`

## 1. 作用

把历史某个时间范围内 **缺失** 的窗口数据，一次性拉齐写回 ADB。用于首次上线、错过增量或数据修复等场景。

- 可指定 **开始 +（可选）结束** 时间
- **结束留空** 时，默认截止到当前 `(now - lag)` 的上一已结束窗口

## 2. 接口与入口

范围补全与窗口补全两条独立入口（互斥：同一时刻仅允许一个补全任务）：

```
POST/GET  /sync/backfill          // 范围补全（全量分页）
 body: { "start": "2026-08-27 00:00:00", "end": "2026-08-27 17:00:00" }
POST      /sync/backfill/windows  // 窗口补全（并行，按异常/指定窗口列表）
 body: { "windows": [{ "startMs": 0, "endMs": 0 }, ...] }   // 单次 ≤ 4000，按 startMs 去重
```

处理链路：

```
HandleBackfill (api/sync.go)
  ├─ 解析 start / end（毫秒时间戳 | "2006-01-02 15:04:05" | RFC3339）
  ├─ 边界对齐：start 向下、end 向上对齐到 interval；无 end 时取 (now-lag) 上一已结束窗口
  ├─ 预估批次数 estBatches = ceil(CountByRangeMs / batch)
  └─ BackfillRangePaged(startMs, endMs, batch, estBatches)   // search_after 全量翻页

HandleBackfillWindows (api/sync.go)
  ├─ 解析、校验并去重 windows（endMs>startMs，按 startMs 去重）
  └─ BackfillWindows(windows, ...)   // 并行同步
```

## 3. 范围补全（BackfillRangePaged，分页）

不切窗口，在整段时间范围上用 `[dateField, _id]` 复合排序做 `search_after` 翻页（同时间戳批次按 `_id` 续翻，不丢不重），每批 `backfill_batch` 条：查 ES → `BuildFromESRecords` 按 id 去重 → `REPLACE INTO` ADB。

- 单线程串行推进，批间按 `backfill_pause_ms` 暂停限流
- 失败批次重试 `max_retry` 次后仅计数 `failed`，**不记录断点/剩余区间**——数据仅供内存展示，重启即失效，失败后整段重跑即可
- ES 查询连续失败会直接中止，终止位置至范围末尾未补全（仅日志提示，无续传）

配置项（`config.yaml` → `sync`）：

| 参数 | 说明 | 默认 |
|---|---|---|
| `backfill_batch` | 单批拉取条数 | 10000 |
| `backfill_pause_ms` | 每批完成后暂停毫秒 | 50（0=不暂停） |
| `max_retry` | 单批 ES/ADB 失败重试次数 | 3 |

## 4. 窗口补全（BackfillWindows，并行）

用于按异常/指定窗口列表补全（对应 `/sync/backfill/windows`）。

| 参数 | 说明 | 默认 |
|---|---|---|
| `backfill_workers` | 并行 worker 数 | 2（不超过 CPU 核数） |
| `backfill_pause_ms` | 每窗口完成后暂停毫秒 | 50（0=不暂停） |

执行流程：

```
BeginBackfill(rangeStart, rangeEnd, totalWindows, firstWindow, lastWindow)
workers = backfill_workers（默认 2，上限 NumCPU）
windows 放入 channel，workers 并发消费
每个窗口：
  1. SyncWindow(win)           // 查 ES（上限 max_size）→ 解析 → 写 ADB（同增量单窗口）
  2. RecordBackfillWindow(res) // 推送 backfill_window 事件
  3. 每完成 5 个窗口或全部结束 → UpdateBackfillProgress
  4. pause_ms > 0 时 sleep，限流
EndBackfill()                  // backfillActive=false，记录 finishedAt
返回 BackfillSummary
```

- 单窗口失败 **不中断** 整批，记入 `summary.windows[].error`
- 结果按窗口 `startMs` 排序；此处的失败明细是本次请求的结果汇报，**非断点续传**

## 5. 监控与 SSE

### 5.1 主页 SSE（`GET /monitor/sse`）

| event | 时机 | 数据结构 |
|---|---|---|
| `backfill` | 范围补全每批 / 窗口补全每 5 窗口 / 结束 | `BackfillProgressPoint` |
| `backfill_window` | 每个批次/窗口完成 | `BackfillWindowPoint` |
| `pipeline` | 实时 + 5s 心跳 | `PipelineSnapshot`（含 `backfillActive`、`backfillProgress`） |

**BackfillProgressPoint**（侧栏 / KPI 用，不含 QPS）：

```json
{
  "at": 0, "atStr": "...",
  "totalWindows": 100, "completed": 60, "failed": 2,
  "totalHits": 4580, "totalWritten": 4560, "percent": 62.0,
  "rangeStart": "2026-08-27 00:00:00.000",
  "rangeEnd": "2026-08-27 01:00:00.000"
}
```

- `percent` = `(completed + failed) / totalWindows * 100`（封顶 100）
- 范围补全下 `totalWindows`=预估批次数、`completed`=已成功批次；窗口补全下为窗口数

### 5.2 详情 SSE（`GET /monitor/backfill/sse`）

打开补全详情弹框时连接，**约 1Hz** 推送 `snapshot`（首包）与 `detail`。

**BackfillDetail** 结构：

| 字段 | 说明 |
|---|---|
| `backfillActive` | 是否进行中 |
| `progress` | 当前 `BackfillProgressPoint` |
| `session` | 会话元信息（开始/结束时间、首末窗口） |
| `qpsSeries` | 每秒 QPS 采样（写入 / 命中 / 窗口） |
| `runtimeSeries` | 服务指标采样（内存 / Goroutine / GC） |

**BackfillSessionMeta**（与 `plan.firstWindow` / `plan.lastWindow` 同形）：

```json
{
  "startedAtMs": 0, "startedAtStr": "...",
  "finishedAtMs": 0, "finishedAtStr": "...",
  "firstWindow": { "startMs": 0, "endMs": 0, "start": "...", "end": "..." },
  "lastWindow":  { "startMs": 0, "endMs": 0, "start": "...", "end": "..." }
}
```

弹框三部分：**本次进度**（含计时器）· **补全吞吐**（QPS 折线）· **服务信息**（运行时折线，单屏无滚动）。

## 6. 响应体

范围补全（`/sync/backfill`，分页模式）：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "plan": {
      "hasEnd": false,
      "mode": "paged",
      "batch": 10000,
      "totalDocs": 123456,
      "totalWindows": 13,
      "rangeStart": { "ms": 0, "time": "2026-08-27 00:00:00.000" },
      "rangeEnd":   { "ms": 0, "time": "2026-08-27 15:59:40.000" },
      "firstWindow": { "startMs": 0, "endMs": 0, "start": "...", "end": "..." },
      "lastWindow":  { "startMs": 0, "endMs": 0, "start": "...", "end": "..." }
    },
    "summary": {
      "totalWindows": 13,     // 实际批次数
      "workers": 0,           // 范围补全串行，恒 0
      "totalHits": 123456,
      "totalWritten": 123450,
      "failed": 0,            // 仅计数，无失败批次明细
      "windows": []           // 范围补全不记录失败明细
    }
  }
}
```

窗口补全（`/sync/backfill/windows`）返回 `{ "windows": <去重后窗口数>, "summary": BackfillSummary }`，其中 `summary.windows` 含失败窗口明细（`error` 非空），`summary.workers` 为实际 worker 数。

## 7. 错误处理

| 场景 | code / HTTP |
|---|---|
| ES 或 ADB 未就绪 | 503 |
| 请求体格式错误 | 400 / code=1 |
| 缺少 start | 400 / code=2 |
| start 无法解析 | 400 / code=3 |
| end 无法解析 | 400 / code=4 |
| 时间范围无效 | 400 / code=5 |

## 8. 与增量的关系

- **增量**：持续、每 `interval` 自动跑当前稳定窗口
- **补全**：一次性回填历史任意范围，分 **范围分页**（整段 `search_after` 翻页）与 **窗口列表并行** 两种
- 窗口补全复用 `SyncWindow`；范围补全整批 `REPLACE INTO`
- ADB `REPLACE INTO` 幂等，重复回填安全
