# 补全（历史回填）逻辑

> 关联代码：`api/sync.go`、`store/sync.go`、`store/monitor.go`、`common/window.go`

## 1. 作用

把历史某个时间范围内 **缺失** 的窗口数据，一次性拉齐写回 ADB。用于首次上线、断点续传、错过增量或数据修复等场景。可指定开始 +（可选）结束时间；不指定结束时间时默认截止到当前 lag 边界。

## 2. 接口与入口

```
POST/GET  /sync/backfill
 body: { "start": "2026-08-27 00:00:00", "end": "2026-08-27 17:00:00" }
```

处理链路：

```
HandleBackfill (api/sync.go)
  ├─ 解析 start/end（支持毫秒时间戳 | "2006-01-02 15:04:05" | RFC3339）
  ├─ CalcBackfillPlan(...)             // 把时间范围切成 N 个 interval 窗口（见《时间计算》）
  ├─ m.BackfillWindows(plan.Windows, ...)   // 并行同步
  └─ 返回 { plan, summary }
```

## 3. 计划计算（CalcBackfillPlan → SplitWindowsMs）

- `intervalMs` = `interval * 1000`，`lagMs` = `lag * 1000`
- `rangeStartMs` = `start` 向下对齐 `interval`
- 结束边界：
  - 有 `end`：`rangeEndMs` = `end` 向上对齐 `interval`
  - 无 `end`：取「(now - lag) 的上一已结束窗口」的结束时刻
- 用 `SplitWindowsMs(rangeStart, rangeEnd, interval)` 切成 `[t, t+interval)` 窗口序列
- `TotalWindows` = 窗口个数；窗口数过大时耗时较长，前端会提示

## 4. 并行执行（BackfillWindows）

```
workers = runtime.NumCPU()        // 并行度
把 windows 全部放入 channel
启动 workers 个 goroutine，各自从 channel 消费窗口
对每个窗口：
   1. SyncWindow(win)      // 查 ES → 解析 → 写 ADB（同增量单窗口逻辑，无保存重试，数据转换见《数据转换逻辑》）
   2. 收集 WindowSyncResult{window, hits, written, error}
   3. 更新进度：每完成 5 个窗口调用 Monitor.UpdateBackfillProgress
全部完成后返回 BackfillSummary
```

- 单个窗口失败不中断整批，只记 `error`
- 结果按窗口 `startMs` 排序回填

## 5. 监控与进度推送

| 事件 | 时机 | 数据结构 |
|---|---|---|
| `backfill` | 每完成 5 个窗口 / 结束 | `BackfillProgressPoint` |
| `backfill_window` | 每个窗口完成 | `BackfillWindowPoint` |

- 开始：`Monitor.BeginBackfill(rangeStart, rangeEnd, totalWindows)`（`backfillActive=true`）
- 结束：`Monitor.EndBackfill()`（`backfillActive=false`）

##### BackfillProgressPoint 字段
`at / atStr / totalWindows / completed / failed / totalHits / totalWritten / percent / rangeStart / rangeEnd`

- `percent` = `(completed + failed) / totalWindows * 100`（封顶 100）
- 前端“补全进度”卡片据此展示：百分比、`命中/写入/失败`、完成窗口数与时间范围

## 7. 错误处理

| 场景 | code / HTTP |
|---|---|
| ES 或 ADB 未就绪 | 503 |
| 请求体格式错误 | 400 / code=1 |
| 缺少 start | 400 / code=2 |
| start 无法解析 | 400 / code=3 |
| end 无法解析 | 400 / code=4 |
| 时间范围无效（end<=start 等） | 400 / code=5 |

## 8. 与增量的关系

- 增量：持续、每 interval 自动跑当前稳定窗口
- 补全：一次性、并行回填任意历史范围
- 两者复用相同的 `SyncWindow` 单窗口同步逻辑和 ADB 写入（REPLACE INTO，天然幂等，重复回填安全）
